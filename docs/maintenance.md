# Регламент підтримки документації

## Головне правило

> **Зміна коду = зміна документації.** Жоден PR не зливається в `main`, якщо він змінює поведінку, структуру або розгортання і не оновлює зачеплені документи паспорта.

Що саме оновлювати:

| Змінилось у коді | Оновити |
|---|---|
| новий / перейменований маршрут, змінений формат відповіді | [SDD §5.2](sdd.md#52-http-контракти-повний-перелік-маршрутів); для `/api/*` — ще й README «Публічний JSON API» |
| новий модуль / blueprint / клас-компонент | [SDD §2–3](sdd.md#3-опис-компонентів) (C4 і таблиця компонентів) |
| нова таблиця, колонка, міграція | [SDD §4](sdd.md#4-модель-даних) |
| сервіс у compose, порядок запуску, порт, Dockerfile | [ISD §1–2](isd.md#2-контейнери-і-порядок-запуску) |
| нова змінна оточення | [ISD §3](isd.md#3-змінні-оточення-без-секретів) і `.env.example` |
| стадія CI, Quality Gate | [ISD §5](isd.md#5-cicd-конвеєр) |
| принципове архітектурне рішення | **новий** ADR; старий отримує статус `Superseded by` |
| поведінка, видима користувачу | README |

## Як правило забезпечується

1. **Автоматично:** `python scripts/doc_audit.py --gate` (див. [ISD §5](isd.md#5-cicd-конвеєр)). Скрипт завершується з кодом 1, якщо:
   * у SDD немає маршруту чи таблиці з коду, у README немає публічного `/api/*` маршруту, в ISD немає сервісу compose чи змінної оточення (структурний дрейф);
   * після останнього оновлення документа паспорта були коміти в код, який він описує («відстає від коду»);
   * минув цикл перегляду документа.
2. **На рев'ю:** у PR відмічається пункт «Документацію оновлено / не потрібно, бо …».
3. **За календарем:** власник переглядає документ не пізніше дати в колонці «Наступний перегляд» і оновлює `last_reviewed` у front-matter.
